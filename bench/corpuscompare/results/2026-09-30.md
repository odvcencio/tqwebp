## Regression isolation and fix

Three current-main q75 ablations isolated the collapse to coefficient
refinement. Trellis is not needed to trigger it; disabling refinement while
retaining probability optimization restores quality. The ablation uses the
root oracle's 8×8 SSIM, which differs from the Gaussian SSIM below.

| Kodak 01 path | Bytes | Root-oracle SSIM |
|---|---:|---:|
| Method 5 | 90,952 | 0.963354 |
| Original method 6 | 15,376 | 0.602768 |
| Original method 6, coefficient refinement disabled | 82,230 | 0.963267 |
| Candidate refinement only, trellis and probability updates disabled | 15,398 | 0.553925 |

[Raw ablations](ablation-2026-09-30.json) also include Kodak 03 and the package
screenshot. Reducing the shared slope for a diagnostic first pass demonstrated
the quality sensitivity; production instead leaves mode selection unchanged
and derives a separate coefficient slope, `(modeLambda + 32) / 64`, for both
candidate refinement and trellis. Both probability passes use the same weight.
This is an empirical, conservative calibration, not an arithmetic or decoder
conformance fix and not a proof of globally optimal rate-distortion search.

## CPU and allocation limits

Across all q75 inputs, median corrected method 6 time is 4.59× method 5
and 5.96× cwebp CLI wall time. cwebp includes process and file overhead;
Go measurements exclude PNG decode and output writes. These ratios are
not a controlled speed comparison with the earlier capture.

Median warmed Go allocation volume is 6.82 MiB/megapixel for method 4,
6.55 for method 5, and 161.04 for corrected method 6. This is total allocation
volume, not peak live memory. A candidate-buffer experiment was reverted
because compiler analysis showed that it still escaped to the heap.
Method 6 is useful for compression experiments and offline assets; its
allocation and CPU costs remain an optimization backlog. Default method 4
and method 5 are the practical choices when throughput matters.

## Validation and remaining gaps

- All 144 files decoded through dwebp with correct dimensions, including
  108 tqwebp outputs. Source hashes and timed-repeat determinism were checked.
- All 72 method 4/5 files are byte-identical to the retained original outputs.
- Full Go tests and race tests passed, including independent reconstruction,
  syntax-cost, probability, image-mode/subimage, and writer-failure tests.
- Public API fuzzing passed 50,547 executions in 30 seconds; independent
  reconstruction fuzzing passed 68,409 in 30 seconds.
- Build, vet, formatting, synthetic release gates, six cross-builds, both
  nested benchmark modules, and fourteen Python gate tests passed.
- A separate consumer module encoded successfully with cgo disabled and
  carried neither `x/image` nor the test oracle in its production imports.
- Current Chrome validation was unavailable: the installed executable
  returned permission denied. Firefox and WebKit were not exercised.
- Large-image stress, sustained fuzzing, peak-RSS measurement, and a broader
  holdout corpus were not run. Alpha, lossless, metadata, animation, loop
  filtering, and production adaptive quantization remain outside scope.

These changes are local and unreleased. They make an opaque lossy encoder
reviewable and dependable within this measured scope; they do not establish
full libwebp feature or performance parity.
